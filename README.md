# ThermoGuard
## Intelligent BESS Thermal Management and Control Systems Laboratory

ThermoGuard is an interactive educational project that simulates four thermally coupled battery zones and provides numerical demonstrations for core control-systems topics. All parameters are illustrative and are not validated measurements from a battery installation.

### Problem, motivation, and objectives
Grid-scale battery enclosures experience spatial temperature differences, time-varying heat generation, imperfect cooling and sensor/actuator faults. A single average reading can obscure a local hotspot. This project compares fixed cooling, conventional average-temperature feedback and a zone-aware heuristic while connecting a locally linearized plant to SISO control theory.

### Architecture and model
`config/default_parameters.py` defines lumped thermal capacitances (J/K), conductances (W/K), and heat generation coefficients (W/A²). `src/thermal_model.py` implements

`Cᵢ dTᵢ/dt = Qᵢ − (h₀ᵢ + βᵢηᵢuᵢ)(Tᵢ−Tₐ) + Σⱼ kᵢⱼ(Tⱼ−Tᵢ)`.

Temperature difference ↔ voltage, heat flow ↔ current, thermal resistance ↔ electrical resistance, and thermal capacitance ↔ electrical capacitance. The simulator uses a fixed-step RK4 integrator, clips actuator commands to [0,1], keeps truth separate from sensor signal, and supports disturbances/faults. Linearization returns A, B, C, D and E for command and heat disturbances. It is a local approximation, distinct from nonlinear simulation.

### Controllers and allocation
Open-loop applies fixed zone commands. PI/PID uses the average measured temperature, common command and saturation. ThermoGuard combines each zone's positive temperature deviation, positive measured rate and heat load into a priority. It derives desired effort with a heat feedforward term and actuator-health compensation, allocates within the total budget by priority, then redistributes spare capacity to zones with remaining command headroom. It is a transparent heuristic, not machine learning or MPC.

### Scenarios and metrics
The dashboard offers normal operation, current step, elevated ambient, Zone 1/2 hotspot, actuator degradation, sensor bias, and combined disturbance options. Metrics include peak temperatures, maximum spatial spread, approximate rise/settling/peak times, overshoot, final tracking error, IAE, time above setpoint+5 K, command peak and `∫Σuᵢ³dt`. That final quantity is an illustrative fan-energy proxy, not an HVAC energy model or field measurement.

### Control Systems syllabus mapping

| Syllabus topic | Relevant module and calculation | Dashboard page |
|---|---|---|
| Open/closed loop, feedback, gain | `src/block_diagrams.py`; response calculation | Module 1 |
| Differential models, thermal RC, LTI/MIMO linearization | `src/thermal_model.py`, `src/linearization.py` | Module 2 |
| Electrical RLC and mechanical mass-spring-damper | `src/electrical_models.py`, `src/mechanical_models.py` | Module 2 |
| Series/parallel/feedback and Mason formula | `src/block_diagrams.py`, `src/signal_flow.py` | Module 2 |
| Step/ramp/impulse and time specifications | `src/time_domain.py` numerical SciPy response/specification extraction | Module 3 |
| Poles, characteristic polynomial, Routh, root locus | `src/stability.py` | Module 4 |
| Bode, polar locus, crossover and margins | `src/frequency_domain.py` | Module 5 |
| P/PI/filtered PID and lead/lag/lead-lag | `src/compensators.py` | Module 6 |
| State-space matrices, eigenstructure, controllability, observability, transition | `src/state_space.py`, `src/thermal_model.py` | Module 7 |

This release does not provide general canonical/Jordan decomposition, a full transfer-function matrix conversion, Nyquist encirclement counting, a detailed cascade-loop simulation, generalized static error constants, nor exported plot files. These are not represented as implemented dashboard features.

### Installation and execution
From this directory:

```bash
pip install -r requirements.txt
streamlit run app.py
pytest -v
```

Use the sidebar to open the BESS simulator, select a scenario, set parameters, and press **Run simulation**. All three policies receive the same simulated profile; use the controller detail selector, CSV download, comparison metrics, and fault inspection views. Laboratory controls recompute the selected SISO demonstration.

### Results and interpretation
Running the app computes live results from the selected values. Numerical demo artifacts and plots are generated by `scripts/generate_results.py` into `results/`. Interpret policy differences as results of this lumped model and these assumptions only. The model omits electrochemical dynamics, spatial gradients within each zone, detailed HVAC thermodynamics, parameter identification and safety certification. Future work could include validated pack data, explicit actuator dynamics, uncertainty studies, richer MIMO analysis and independent physical model validation.
